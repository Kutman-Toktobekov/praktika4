# Практическая работа № 4. Потоки

## Цель работы

Изучить различия между потоками и процессами в Linux, измерить время выполнения вычислительной и сетевой задач, объяснить результаты с учётом GIL в CPython.

## Среда выполнения

- ОС: Ubuntu в WSL2
- Python: 3.10.12
- Доступно процессоров: 12
- Число потоков/процессов в тестах: 4
- Повторы каждого измерения: 3
- Метрика: медиана времени трёх запусков

Примечание: методические указания рекомендуют Python 3.11+, а эксперимент выполнен на Python 3.10.12.

## Файлы проекта

- `generate.py` — создаёт файл с числами.
- `numbers.txt` — 10 000 000 целых чисел.
- `sum_benchmark.py` — сравнивает последовательное суммирование, 4 потока и 4 процесса.
- `network_benchmark.py` — сравнивает три способа загрузки 20 URL с локального HTTP-сервера.
- `README.md` — отчёт о работе.

## Часть 1. Суммирование чисел

Для эксперимента создан файл `numbers.txt`, содержащий 10 000 000 чисел от 1 до 10 000 000. Размер файла — около 76 МБ.

Запуск:

```bash
python3 generate.py
python3 sum_benchmark.py
```

Ожидаемая сумма:

```text
50000005000000
```

### Результаты

| Способ | Запуск 1, с | Запуск 2, с | Запуск 3, с | Медиана, с |
|---|---:|---:|---:|---:|
| Один поток | 0.463 | 0.420 | 0.433 | 0.433 |
| 4 потока | 0.509 | 0.491 | 0.493 | 0.493 |
| 4 процесса | 0.179 | 0.183 | 0.172 | 0.179 |

Все три способа вычислили одинаковую сумму.

### Объяснение результатов

- Один поток оказался быстрее четырёх потоков. В CPython действует GIL (Global Interpreter Lock), который ограничивает одновременное выполнение Python-кода, интенсивно использующего CPU, несколькими потоками одного процесса.
- Четыре потока не дали ускорения: дополнительные расходы на переключение и координацию потоков оказались больше возможной выгоды.
- Четыре процесса оказались быстрее одного потока в данном эксперименте. Процессы могут выполнять вычисления параллельно, поскольку каждый процесс имеет собственный интерпретатор Python.
- У процессов есть дополнительные расходы на создание и координацию, поэтому результат зависит от задачи, объёма данных и среды выполнения.

## Часть 2. Сетевые запросы

Программа выполняет 20 HTTP-запросов к локальному серверу. Сервер искусственно задерживает ответ на 0.05 секунды, чтобы смоделировать ожидание сети.

Запуск:

```bash
python3 network_benchmark.py
```

### Результаты

| Способ | Запуск 1, с | Запуск 2, с | Запуск 3, с | Медиана, с |
|---|---:|---:|---:|---:|
| Последовательно | 1.057 | 1.053 | 1.053 | 1.053 |
| ThreadPoolExecutor | 0.287 | 0.284 | 0.274 | 0.284 |
| ProcessPoolExecutor | 0.293 | 0.288 | 0.293 | 0.293 |

### Объяснение результатов

- При последовательной загрузке каждый запрос ожидает завершения предыдущего.
- `ThreadPoolExecutor` позволяет выполнять несколько запросов одновременно. Пока один поток ждёт ответ, другие потоки могут выполнять свои запросы.
- `ProcessPoolExecutor` также ускорил выполнение по сравнению с последовательным способом, но для этой задачи дополнительные расходы на процессы не дали преимущества перед потоками.
- В сетевых задачах потоки полезны, потому что значительная часть времени уходит на ожидание ввода-вывода, а не на вычисления CPU.

Этот тест использует локальный сервер и искусственную задержку, поэтому его результаты не являются измерением скорости реального интернета.

## Общий вывод

Потоки и процессы подходят для разных типов задач.

Для задач, которые преимущественно ждут ввода-вывода, например сетевых запросов, часто подходят потоки. Они позволяют использовать время ожидания для выполнения других запросов.

Для вычислительных задач в CPython процессы могут дать ускорение, поскольку несколько процессов могут выполнять Python-код параллельно. Однако создание процессов и организация обмена данными требуют дополнительных ресурсов.

В проведённом эксперименте четыре потока не ускорили подсчёт суммы, а четыре процесса показали наименьшее время. При загрузке 20 URL потоки и процессы значительно ускорили работу по сравнению с последовательным способом, причём потоки оказались немного быстрее.

Результаты относятся к данной программе и данной среде выполнения; при другой реализации или на другом компьютере они могут отличаться.

## Часть 3. Общая память потоков и процессов

Запуск: `python3 memory_demo.py`

### Результат

Поток изменил общий список, и изменение осталось видимым в главном потоке.

Дочерний процесс изменил собственную копию списка, поэтому список главного процесса не изменился.

### Вывод

Потоки одного процесса используют общее адресное пространство. Процессы имеют отдельные адресные пространства. Для обмена данными между процессами можно использовать очереди или разделяемую память.
